0.2.5 (beta) · Works on Windows without English text recognition; maximized windows; says why OCR failed

• Reported on GitHub (#2, #3): on a Windows set up in another language,
  Background stopped right away with "Windows could not read the
  confirmation. No confirmation click sent." Windows had no English text
  recognition (OCR) installed. The app now uses English OCR if any variant is
  installed, otherwise another Latin-script OCR language such as Portuguese or
  Spanish. It still checks every item name, price and button strictly, so a
  misread stops the run without a click.
• If Windows OCR still cannot be used, the stop message now gives the actual
  reason, for example which OCR languages are installed and how to add English,
  instead of the generic message. Non-English Windows error text no longer
  crashes the reader.
• Maximized or other windows wider than 16:9 (for example 1920 × 1009 or
  3840 × 2019): the game keeps its buttons and labels the same shape in a wider
  window, but the app squeezed the whole window into 16:9 and then compared it
  with 16:9 pictures. The shop title only just passed, so the run could stop
  with "The Secret Shop did not open" or "The shop did not return after
  confirmation", and Covenant/Mystic icons were found only by their names. The
  app now also compares against the squeezed shape, so these windows match as
  well as 16:9 ones.
• "The shop did not return after confirmation" now saves pictures of the shop
  title, Refresh label and dialog area, and shows how well each matched.
• Shop rows: a stock count read in pieces ("1" and "/1") is joined back
  together, and a small category label ("Currency") that OCR lost is read again
  from its own strip. A row that shows two category, price or Buy words in any
  read is still refused.

0.2.4 (beta) · A mouse resting on the game no longer cancels clicks; recovers from ignored clicks

• Windows: the game cancels a Background click while your mouse rests
  anywhere on it, so the shop icon was pressed but the shop
  never opened ("The Secret Shop did not open after selecting its menu").
  The same happens in fullscreen. Background now pauses while the mouse is
  over the game, still or moving, windowed or fullscreen, and resumes when you
  move it off: onto the compact tracker bar, the taskbar or another screen.
• Copy report: when a run stops with a problem, one click copies a short report
  to paste on Reddit or GitHub: version, system, mode, game window size,
  windowed or fullscreen, display scaling, the stop reason, the newest failure
  record and the last 60 log lines. Your Windows user name is replaced with
  <user>. Open pictures opens the screenshots saved when the run stopped.

• Reported on STOVE: buying an item in the last row of the scrolled shop stopped
  the run. Right after that purchase the game can ignore a click, leaving a
  dialog open ("The shop did not return after confirmation") or opening none.
• If the very same Confirm dialog is still open and settled 5 seconds after the
  click, the app confirms once more. One dialog is one purchase or one refresh,
  so this cannot charge twice. Before, this retry needed a pointer pause.
• If a Buy click opens no dialog, the app clicks Buy once more, only on the fully
  visible shop with the same item and Buy button. Buy spends nothing on its own.
• If a Refresh click opens no dialog ("The refresh confirmation was not
  recognized"), the app clicks Refresh once more, only on the fully visible shop
  with the Refresh button where it was. Refresh spends nothing on its own.
• Waits 0.6 seconds after a purchase from the scrolled list before Refresh.
• Each retry happens at most once; a second miss stops the run as before.
• Two wanted items on the same page: after buying the first, the app looked
  for the second while the list was still moving and stopped with "The
  selected item changed before Buy". It now waits for the list to come to rest
  after each purchase before looking for the next item.
• Windowed games: a mouse crossing the game during the app's scroll could
  cancel it, so the second half of the shop was never checked and a wanted
  item there was skipped. The app now checks that the list moved and drags
  once more if it did not. If it still did not, it drags the other way (a shop
  left scrolled to the bottom then shows its top rows); if the list never
  moves, the run stops before Refresh. A drag spends nothing.
• Tap delay is now at least 0.3 seconds, the default. Lower values, including
  ones saved by older versions, are raised to 0.3: faster clicking makes the
  game ignore clicks.
• Copy report also hides short Windows user names in profile paths.
• An item bought by hand before the run started could be tried again, stopping
  at the Buy dialog. The app now also skips a row the game shows greyed out.
• Mouse mode no longer shrinks to the always-on-top compact bar: over the game
  it hid what Mouse mode reads from the screen, and the run stopped.
• Random timing no longer draws a click delay below the 0.3 second floor.
• If the item list was still moving right before Buy, the run stopped with
  "The selected item changed before Buy". It now waits for the list to settle
  and looks once more; it still stops, with no click, if the item is gone.
  The same applies when the moving list made the item's price and Buy button
  unreadable ("could not be verified on the same row").
• Steadier, a little slower: Mouse and Background now wait until every row of
  the item list has stopped moving (not just the list on average) before
  reading it, with a longer upper bound after a refresh.
• Fewer stops from a single unlucky frame, none of them after a click: right
  before Buy the app looks up to three times (settling in between) before
  stopping; a frame where a fade or toast hides the shop title is read again
  instead of stopping; a Refresh button covered by a toast gets 5 seconds
  instead of 2.5; a momentarily blank game capture is taken again once.
• A Confirm dialog whose pixels keep changing (an animated glow) while its
  button stays in place no longer stops the run with "The confirmation kept
  changing while being read". A button held still for 1 second counts as
  settled; the dialog's item and price are still checked before Confirm.
• STOVE: Windows OCR read the coin icon beside the Covenant price as a
  leading 0 ("0184,000"), so the dialog was rejected as the wrong price and
  the run stopped. Prices are now compared as numbers; any other extra or
  different digit is still rejected.
• Windowed games: if a passing pointer cancelled the scroll, one odd frame
  could pass for a scrolled list, so page two was really page one again. The
  app now confirms the frame is the shop before judging whether it scrolled.
• If a run stops right after a Confirm click was sent but before the shop came
  back, that refresh or purchase is counted once, and the log says its result
  was not seen, so you can check it in the game.

0.2.3 · A refresh dialog the game ignored no longer stops the run

• If the game ignored a Confirm click (for example right after a purchase that
  followed a scroll), the shop dimmed behind the still-open "Use Skystone to
  refresh?" dialog could be taken for the shop. The refresh was counted and the
  next Refresh click went into the dialog, stopping with "The refresh
  confirmation was not recognized". The shop now has to be fully visible, not

  the app waits for an overlay to clear instead.

  and the built-in images are used instead.

  read again for up to 2.5 seconds instead of stopping the run. Still only one
  Refresh click; a screen that is not the shop stops at once as before.
• If a pointer pause swallows the Secret Shop menu click on the home screen,
  the app checks the home screen again and reselects the menu, up to 3 times.

0.2.0 · Background mode for Steam, Linux support and faster refreshes

• New Background control mode for Epic Seven on Steam, on Windows 11 and
  Linux (Proton). It never uses your pointer or keyboard focus: the game may
  be unfocused or covered by other windows. Input pauses while the pointer is
  over the game and resumes once it has been still for a second. Steam E7 runs
  as administrator on Windows, so starting offers the administrator restart.
• Linux: the GUI runs from source and offers Background mode only.
  e7-shop-refresh-linux.sh checks system packages (it prints the install
  command and never runs sudo), sets up Python, builds the input helper,
  starts the GUI and can add an app-menu entry. The global Stop key works on
  X11; Wayland sessions are refused.
• Faster Background and Mouse refreshes: waits now end as soon as the screen
  shows the expected state, with the old fixed times kept as upper limits.
  Measured on Windows Steam at 2560 × 1440: about 5–6.5 seconds per refresh,
  down from about 8.5. ADB keeps its fixed waits.
• The tap delay is now the minimum gap between clicks, and the final dialog
  check happens after it, just before the click.
• Windows text recognition keeps one reader running instead of starting one
  per read (about 0.04 seconds per read instead of 0.44).
• Compact tracker (on by default): once the engine starts, the window shrinks
  in place to a small always-on-top bar with Covenant, Mystic and Friendship
  buys, Skystones spent, time left and Stop. The full window returns when the
  session stops, finishes or needs attention, from the bar's expand button or
  its close button (which does not stop the session); the header's Compact
  button shrinks it again. Calibration keeps the full window. Turn it off under "Compact tracker while running".
• The About window names the platform it runs on instead of always "Windows".
• Start and end sounds are 10 dB quieter.
• Refuses to start when more than one Epic Seven window is open.
• Tested on Windows 11 with Steam E7: live sessions at 3840 × 2019 and
  2560 × 1440 (also over Moonlight), with Friendship and Covenant purchases at
  2560 × 1440;
  dry runs at 1920 × 1080 and 1280 × 720. On Linux Mint 22 a live session
  bought a Covenant bookmark and Friendship points. Other display scaling settings, ultrawide windows and
  other Linux desktops are untested.
• Includes all 0.1.4 trial changes below (rc1–rc9), which had no stable
  release.
